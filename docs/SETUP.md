# SETUP.md

1. Copy .env.example to .env and set DISCORD_TOKEN, DISCORD_VOICE_TOKENS and DISCORD_GUILD_ID. NOSTR_RELAYS already defaults to the live GitHub Pages relay set; set optional ZELLOUS_RELAYS only to override it. No owner relay-set confirmation remains.
2. Keep .env at mode 600. It is ignored by git and excluded from every witness.
3. Create one Discord application and bot user per voice identity. Put every voice bot token in DISCORD_VOICE_TOKENS as a comma-separated list. Invite each bot to guild 367741339393327104 with View Channel, Connect, Speak and Request to Speak.
4. Leave DISCORD_PRIVILEGED_INTENTS=false to run the control-plane bridge with GUILDS, GUILD_MESSAGES, GUILD_MESSAGE_REACTIONS, GUILD_MESSAGE_TYPING and GUILD_VOICE_STATES. Set it to true only after enabling MESSAGE_CONTENT, GUILD_PRESENCES and GUILD_MEMBERS in the Developer Portal. With the switch off, /health reports message-content, presence and member-list enrichment as degraded.
5. Run npm ci --ignore-scripts, npm run live:alignment, npm run alignment:red-check, npm run typecheck, npm run unit, npm run integration, npm run secret:scan, npm run build, npm run config:check, npm run intent:guard, npm run intent:red-check and npm run serve:check.
6. Run npm run cleanup once when owner-authorized duplicate cleanup is intended. It preserves canonical channels, deletes only bridge-created duplicates, deduplicates relay snapshot entries, writes cleanup-backup.json and reports exact before/after counts and IDs. npm run cleanup:rollback restores the previous snapshot and recreates duplicate channels with new IDs. npm run cleanup:red-check proves no canonical channel is deleted and no new duplicate appears after read-only startup. Then run npm run snapshot:reconcile, npm run snapshot:rollback and npm run snapshot:red-check for the earlier relay-only reversible reconciliation. npm run serve is read-only by default because LIVE_INVENTORY_MODE=read-only; set LIVE_INVENTORY_MODE=reconcile only when writes are intended. Then run npm run health, npm run live:inventory and npm run live:voice.

The service uses BRIDGE_PRIVATE_KEY_HEX from the ignored .env for owner-signed publication and writes state to the ignored data directory at mode 600. Logs use structured redaction and never print secret values. Open note: chat-exposed owner key rotation risk remains; the existing key is used without echoing it.

If DISCORD_VOICE_TOKENS has fewer than two entries, per-user voice reflection is degraded and live voice smoke reports VOICE_POOL_ABSENT. This is an owner credential gap, not a skipped check. Mixed audio is never used as a substitute. /health reports voiceReflectionComplete false and per-user-voice-reflection in degradedFeatures.

Read docs/OPERATOR_RUNBOOK.md before supplying credentials or resuming the final window. It states the exact DISCORD_VOICE_TOKENS shape, per-bot permissions, chosen live relay default, optional ZELLOUS_RELAYS override, token redaction rules and the reason only voice acceptance remains held. Portal intent approval and relay-set confirmation are not held; text reflection works with privileged intents off.
